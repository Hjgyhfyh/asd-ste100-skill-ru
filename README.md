# Навык `ste` — упрощённый технический русский

Русская версия навыка [danyuchn/asd-ste100-skill](https://github.com/danyuchn/asd-ste100-skill). Исходный навык переписывает английский текст по правилам ASD-STE100 (Simplified Technical English). Здесь то же самое сделано для русского: структурные правила STE перенесены на русский язык, а лексическая часть переписана под русские особенности.

## Что изменилось по сравнению с оригиналом

| Оригинал (английский) | Эта версия (русский) |
|---|---|
| Ограничение на фразовые глаголы («spin up», «take off») | Ограничение на канцелярит («в целях», «является», «имеет место») |
| Список рекламных прилагательных на английском | Список на русском: «уникальный», «безупречный», «инновационный», «мгновенный» |
| Отглагольные существительные («perform an analysis») | Отглагольные существительные («осуществлять настройку», «оказать помощь»), в том числе в предложном падеже («при обработке») |
| Present Perfect запрещён | Запрещён страдательный залог и причастия: «была выполнена проверка» → «агент выполнил проверку» |
| Цепочки существительных из 3 слов | То же, с разворотом предлогами |
| Нет правила про язык | Отдельное правило: брать устоявшийся русский термин вместо англицизма, если он есть |
| Нет правила про различение понятий | «Ошибка» / «сбой» / «отказ» / «дефект» / «неисправность» — пять разных вещей, их нельзя чередовать |
| — | Новое правило: сложные подчинения (два и больше придаточных в одном предложении) |

Осторожность («возможно», «мог», «вероятно») не трогается ни одним правилом и линтером: уверенность автора — это содержание, а не стиль.

## Установка

Скопируйте папку навыка в каталог пользовательских навыков вашего агента:

- DeepSeek Harness на Windows: `%USERPROFILE%\.agents\skills\ste`
- Другие агенты на базе Agent Skills: `~/.agents/skills/ste`

Харнесс подхватывает новый навык без перезапуска.

## Как пользоваться

Три способа:

1. **Команда.** Напишите в чат `/ste` и следуйте строкой текст, который нужно переписать. Навык подставится целиком.
2. **Обычными словами.** «Упрости этот текст», «перепиши понятнее», «убери двусмысленность» — навык сработает сам по описанию.
3. **Вручную.** Попросите модель загрузить навык `ste` через инструмент `skill`.

По умолчанию на выходе только переписанный текст. Попросите «покажи разбор» — выведется таблица «нарушенное правило / было / стало».

## Файлы

| Файл | Что внутри |
|---|---|
| `SKILL.md` | Сам навык: когда применять, два режима, таблицы правил, процесс, формат ответа, границы |
| `references/pravila.md` | Сводка 9 разделов правил ASD-STE100, структура словаря, раздел о переносе правил на русский, источники |
| `examples/primery.md` | Примеры «до и после»: правила на русском и четыре реальных случая (описание инструмента, сообщение об ошибке, инструкция между агентами, проза README) |
| `scripts/ste-lint.py` | Линтер структурных правил, только стандартная библиотека Python |

## Линтер

```bash
python scripts/ste-lint.py файл.md          # проверить файл
python scripts/ste-lint.py --json файл.md   # структурированный вывод
echo "текст" | python scripts/ste-lint.py   # стандартный ввод
python scripts/ste-lint.py --baseline 5 файл.md   # не падать, пока нарушений не больше 5
python scripts/ste-lint.py --disable канцелярит файл.md
python scripts/ste-lint.py --selftest       # проверить сам линтер
```

Жёсткие правила: `точка-с-запятой`, `длинное-предложение` (потолок 20 слов), `канцелярит`, `отглагольные-существительные`, `рекламное-прилагательное`, `синонимная-ротация`, `многосоюзность`, `сложные-подчинения`, `висячий-союз`.

Рекомендательные правила (никогда не роняют прогон): `страдательный-залог`, `причастный-оборот`, `предложный-отглагольный`.

Линтер проверяет потолок в 20 слов. Для инструкций (15 слов) считай сам.

Предложения склеиваются по абзацу, поэтому перенос строки в Markdown не прячет длинное предложение от проверки. Блоки кода между ``` не проверяются ни на длину, ни на другие правила. Ячейки таблиц и встроенный код в обратных кавычках проверяются: длина ячейки считается по её тексту, а текст в кавычках перед подсчётом слов убирается.

Оговорки и модальность не отмечаются никогда. Это проверяется в `--selftest`, вместе с проверкой на ложные срабатывания.

Линтер можно гонять по документам самого навыка. Он найдёт в них нарушения, и это ожидаемо: таблицы правил и `examples/primery.md` обязаны цитировать нарушающий текст, иначе пример перестанет быть примером. Не «чините» цитаты в колонке «Было» и не сокращайте объяснения в колонке «почему это плохо». Точка с запятой при этом в документах навыка не используется нигде, кроме намеренных цитат.
